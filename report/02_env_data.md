## 2. Формальная спецификация среды

Среда — кооперативная частично наблюдаемая стохастическая игра (Dec-POMDP) ⟨N, S, {Aᵢ}, P, R, {Oᵢ}, γ, T⟩. Реализация — `src/env.py`, векторизована на PyTorch, API в стиле PettingZoo (наблюдения агентов, маски действий, глобальное состояние для CTDE).

| Элемент | Спецификация |
|---|---|
| Агенты N = 4 | 0 — эксперт по тексту метаданных; 1 — эксперт по временному ряду звука; 2 — эксперт по спектрограмме; 3 — координатор качества |
| Эпизод | поток из T = 50 треков, поступающих в каталог; бюджет ручной проверки B = 15 треков (30%) |
| Наблюдение эксперта i (13) | вероятности своей модели модальности по текущему треку (4), её нормированная энтропия, остаток бюджета B_t / B, доля пройденного эпизода t / T, «репутация» эксперта (сглаженная доля верных голосов по трекам, уже проверенным модератором в этом эпизоде), one-hot агента |
| Наблюдение координатора (13) | максимальные вероятности трёх модальностей, признаки согласия (все три согласны / хотя бы две), средняя энтропия, B_t / B, t / T, one-hot |
| Глобальное состояние s (17) | вероятности всех трёх модальностей (12), B_t / B, t / T, репутации трёх экспертов. Используется только критиками и миксерами при обучении (CTDE) |
| Действия эксперта | {0..3} — голос за класс (male, female, group, instrumental), 4 — воздержаться |
| Действия координатора | 0 — автометка по большинству голосов (ничья решается уверенностью), 1 — отправить модератору |
| Переход | следующий трек потока; если трек проверен, B уменьшается на 1, и модератор раскрывает истинную метку, которая обновляет репутации экспертов |
| Награда (общая) | +1 верная автометка; −3 ошибочная автометка (ошибка в каталоге портит поиск и рекомендации); −0,4 ручная проверка (транзакционные издержки, метка верна); −0,5 трек без метки (все воздержались и проверки нет); −1 нарушение (запрос проверки при B = 0, тогда метка ставится по голосам) |
| Ограничения | жёсткое: бюджет B. SLA качества: доля ошибок среди автометок ≤ 10% в эпизоде (контролируется как метрика нарушений) |
| Завершение эпизода | после T = 50 треков; γ = 0,99 |
| Информация только из прошлого | вероятности модальностей считаются по текущему треку (доступны при загрузке); репутация — только по уже проверенным трекам; будущие треки и метки не наблюдаются |

**Экономика награды.** Автометка выгоднее проверки, когда вероятность её правильности p удовлетворяет условию 1·p − 3·(1 − p) > −0,4, то есть p > 0,65. Агентам нужно научиться:
- оценивать надёжность голосования — с этим помогают воздержание и согласие экспертов;
- расходовать бюджет на трудные треки, а не на первые попавшиеся.

## 3. Паспорт данных

**Источник наблюдений** — вероятности трёх модальных моделей из ЛР2 (логистические регрессии на TF-IDF текста, 120 статистиках ряда, CLIP-эмбеддинге спектрограммы) для треков MTAT и Jamendo. Сами данные описаны в паспортах ЛР2.

**Защита от утечки:**
- для обучающей части MTAT вероятности получены **out-of-fold** (GroupKFold = 5 по исполнителям), поэтому модель модальности ни разу не видела трек, по которому даёт вероятность;
- для val, test и Jamendo используются модели, обученные на всём MTAT train;
- без этого агенты учились бы на завышенной уверенности моделей.

| Часть | Роль | Треков | Исполнителей | male / female / group / instr. | Точность: текст / ряд / изображение | Все три согласны | Точность при согласии |
|---|---|---|---|---|---|---|---|
| MTAT train | обучение политик | 5 071 | 163 | 26 / 25 / 14 / 35% | 0,51 / 0,67 / 0,66 | 34% | 0,91 |
| MTAT val | выбор чекпойнта | 1 019 | 34 | 26 / 25 / 15 / 34% | 0,44 / 0,66 / 0,61 | 29% | 0,88 |
| MTAT test | отложенный тест | 1 009 | 33 | 26 / 25 / 14 / 35% | 0,61 / 0,69 / 0,65 | 38% | 0,93 |
| Jamendo 2005–2009 | стресс (другой каталог) | 130 | | | | | |
| Jamendo 2010–2017 | полностью отложенный период и «сектор» | 151 | | | | | |
| Jamendo всего | | 281 | 106 | 41 / 13 / 10 / 36% | 0,32 / 0,46 / 0,64 | 24% | 0,79 |

**Калибровка вероятностей модальностей (ECE):** на test — текст 0,069, ряд 0,038, изображение 0,028; на Jamendo — 0,346 / 0,196 / 0,053. На новом каталоге текст и ряд становятся сильно переуверенными. Это главный источник сдвига распределения для агентов.

### Проблемы качества и решения

| Проблема | Решение / учёт |
|---|---|
| Утечка уверенности моделей модальностей на train | out-of-fold вероятности |
| В MTAT нет временного порядка и дат | эпизоды — случайные последовательности треков; временная проверка — Jamendo по годам релиза |
| Val сложнее теста (другие 34 исполнителя: текст 0,44 против 0,61) | чекпойнт выбирается по val (консервативно); тест не используется для настройки |
| В MTAT несколько клипов одного трека | могут встретиться в одном эпизоде; эффект на доверие экспертов не исключён (ограничение) |
| Метки слабые (теги / описания) | модератор в среде раскрывает «истинную» метку набора; реальный модератор может с ней не совпасть |
| Сдвиг калибровки на Jamendo | стресс-тест; гармонизация аудио из ЛР2 уже применена |

### Схема разбиения

```
MTAT train (OOF-вероятности) -> обучение всех политик (1,92 млн переходов на запуск)
MTAT val                    -> выбор лучшего чекпойнта (каждые 20 итераций), подбор порога эвристики
MTAT test                   -> основное сравнение (256 эпизодов, общие для всех алгоритмов)
Jamendo 2010-2017           -> полностью отложенный период + другой каталог («сектор»)
Jamendo 2005-2009, пропуск модальности, бюджет x0,5, цена ошибки -5 -> стресс-тесты
```
